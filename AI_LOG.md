   > чтобы денежные расчёты и округления были верными, нельзя использовать float, график рассрочки
   > без потери копеек, идемпотентность платежей реализовать, переходы статусов, Webhook и
   > конкурентные запросы, валидацию данных реализовать. Рассмотреть ограничения в самом задании и
   > логике платежей, проанализируй PDF и напиши этапы выполнения, будем постепенно делать и
   > отправлять на гит, коммитить буду я, текст коммита пиши

   Контекст: PDF задания и сразу акцент на рисках платёжного домена. Код сначала не просил — нужен был
   разбор и план по этапам. На вопросы модели по неоднозначностям ответил: `discount` — сумма в
   копейках, тот же `Idempotency-Key` с другим телом — 409.

2. **Предупреждение из редактора:** вставил текст Pylance про `asynccontextmanager` и написал
   «эта штука устарела».

3. **Разбор ревью:** передал отчёт сессии-ревьюера и попросил «проанализируй, что нужно исправить, и
   напиши текстом, что будем исправлять, перед тем как писать код». Решения по спорным пунктам принял
   сам: на любой несуществующий id — 404, на другое тело с тем же ключом — оставить 409, 404 отдавать
   в формате `{"error": "payment_not_found"}`.

4. **Вопрос к решению модели:** «а зачем две БД нам? SQLite и PostgreSQL?» Модель объяснила роли
   и цену двух баз и рекомендовала оставить обе. Я решил иначе — «сделай постгрес только»: одна БД,
   как в продакшене, конкурентность проверяется на настоящих блокировках строк, запуск через
   `docker compose up`.

## Где модель ошибалась и как это заметили

- **Устаревшая аннотация.** `-> AsyncIterator[None]` у `lifespan` под `@asynccontextmanager`.
  Заметил я по предупреждению Pylance; исправили на `AsyncGenerator[None, None]`.
- **`strict=True` на всю схему запроса.** Хотела запретить `"2"` → `2`, но упали 25 тестов: FastAPI
  валидирует уже разобранный JSON, и строгий enum не принимает строку `"card"`. Поймали тесты;
  `strict` оставили только на числовых полях.
- **Тесты конкурентности, которые ничего не проверяли, — дважды.** На SQLite тест «10 потоков с
  одним `Idempotency-Key`» проходил даже без обработки `IntegrityError`; модель нашла это мутацией,
  добавили `threading.Barrier` и детерминированный тест гонки через `monkeypatch`. После перехода на
  PostgreSQL Barrier-тесты снова перестали ловить поломки — запрос выполняется быстрее разброса
  между потоками, — и атомарность смены статуса не проверял ни один тест. Нашёл третий раунд ревью.
  Добавили детерминированный тест: отдельное соединение держит блокировку строки, оба вебхука
  встают в очередь (ждём по `pg_stat_activity`), блокировка снимается. Вариант «прочитать →
  записать» он ловит 10 из 10, а остальные 198 тестов на нём зелёные.
- **500 на огромный `tariff_id`.** `9223372036854775808` давал `OverflowError` в SQLite (тогда проект
  ещё работал на нём) — у поля
  была только нижняя граница. Модель это пропустила, нашла сессия-ревьюер. Ограничили максимумом
  `INTEGER` PostgreSQL, а не SQLite, чтобы ошибка не вернулась после перехода на Postgres.
- **Слабые места, найденные ревью:** `installment_months: 3.0` принимался (к `Literal` нельзя
  применить `strict`), `EmailStr` молча переписывал `"Иван <ivan@…>"` в адрес, а один тест сверял
  сумму графика с `amount` из того же ответа — то есть проверял данные сами на себе.
- **Автогенерированная миграция была нерабочей.** `alembic --autogenerate` вставил тип приложения
  `app.db.UTCDateTime` без импорта и задублировал CHECK-ограничения enum. Модель заметила при
  чтении миграции, исправила вручную и сверила итоговый SQL через `alembic upgrade head --sql`.
- **Docker Compose не собирался.** У `migrate` и `app` было и `build: .`, и одно имя образа —
  параллельная сборка падала с «already exists». Нашлось при первом `docker compose up`.
- **Подпись вебхука — второй раунд ревью.** Ревьюер мутацией показал, что тесты не ловят подпись
  от пересобранного JSON вместо сырых байтов: тесты подписывали `json.dumps(...)`, и пересборка
  давала те же байты. Там же выяснилось, что README обещал «неподписанный запрос получает 401», а
  битый JSON получал 422: FastAPI разбирает тело раньше зависимостей. Проверку перенесли в свой
  класс маршрута — до разбора тела, — добавили тесты с телом в нестандартном формате; обе мутации
  теперь ловятся.
