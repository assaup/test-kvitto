# Правила для ИИ-ассистента

Сервис платежей на FastAPI (тестовое задание Квитто). Обзор и решения — в README.md.

## Команды

- Миграции: `alembic upgrade head`; новая — `alembic revision --autogenerate -m "..."`
- Запуск: `uvicorn app.main:app --reload`
- БД: только PostgreSQL — `docker compose up -d db` (порт 5433 на хосте)
- Тесты: `pytest` (база `kvitto_test`; тесты очищают таблицы — только база с суффиксом `_test`)
- CI: `.github/workflows/ci.yml` — ruff и pytest с PostgreSQL на каждый push
- Линтер и формат: `ruff check .` и `ruff format .`

Перед тем как считать задачу готовой, `pytest` и `ruff check .` должны проходить.

## Деньги — главное

- Все суммы — `int` в копейках. Никогда не использовать `float`, `round()` и деление `/` для денег.
- Вся денежная арифметика — в `app/money.py`, чистыми функциями с тестами в `tests/test_money.py`.
- Округление процента — половина копейки вверх: `(amount * percent + 50) // 100`.
- Копейки не теряются: `amount + discount == price`, `sum(schedule) == amount`.
- Сумму платежа считает сервер по тарифу из БД; не добавлять в запрос поля с суммами.

## Статусы и конкурентность

- Переходы статусов — только через `ALLOWED_TRANSITIONS` в `app/enums.py`.
- Статус меняется одним атомарным `UPDATE ... WHERE status IN (...)` (`app/services/webhooks.py`).
  Не заменять на «прочитать → проверить в Python → записать»: это гонка.
- Дубли платежей предотвращает UNIQUE на `idempotency_key`, а не предварительный SELECT.
  Обработку `IntegrityError` в `create_payment` не удалять.

## Валидация и ошибки

- У каждого целого числа из запроса, которое попадает в БД, — верхняя граница (`le=DB_INT_MAX`),
  иначе огромное значение даёт 500 вместо 422.
- Числовые поля запроса — `strict=True`: `"2"`, `2.0` и `true` не должны превращаться в `int`.
- `assert` не использовать для проверок в рабочем коде: при `python -O` они отключаются.
- 422 — только стандартный формат FastAPI. Бизнес-ошибки (404, 409) — `ApiError` с телом
  `{"error": "<код>"}`.
- Несуществующий или некорректный id платежа — 404 `payment_not_found`, а не 422.

## Подпись вебхука

- Проверка `X-Signature` — зависимость `verify_signature`, выполняется до валидации тела.
  Не переносить её внутрь обработчика: неподписанный запрос должен получать 401, а не 422.
- Подпись считается по сырым байтам `await request.body()`, а не по пересобранному JSON.
- Сравнение только через `hmac.compare_digest` по bytes; никаких `==`.
- Без `WEBHOOK_SECRET` вебхуки отклоняются. Не добавлять секрет по умолчанию в код.
- Тесты создают приложение через `create_app(make_settings(...))` — явные настройки, не `.env`.

## Схема БД

- Любое изменение моделей — только вместе с миграцией в `migrations/versions/`.
  `create_all` в приложение не возвращать.
- Автогенерированную миграцию читать построчно: типы приложения (`UTCDateTime`) заменять на базовые
  `sa.*`, убирать дубли CHECK для `sa.Enum(create_constraint=True)`.
- Имена ограничений задаёт naming convention в `app/db.py` — в моделях указывать короткое имя.
- `tests/test_migrations.py` должен проходить: он ловит расхождение моделей и миграций.

## Код

- Слои: `routers/` — только HTTP (коды ответов, ошибки), `services/` — бизнес-логика, `money.py` —
  расчёты без БД и FastAPI.
- Типы везде, комментарии на русском и только там, где неочевидно «почему».
- Проще лучше: код должен объясняться построчно. Не добавлять зависимости без необходимости.

## Тесты

- Каждый новый сценарий — тест, который проверяет результат (данные в БД, суммы, статус),
  а не только код ответа.
- Ожидаемые значения в тестах писать из требований, а не импортировать из проверяемого кода и не
  брать из того же ответа.
- Для конкурентности — потоки с `threading.Barrier`; проверять, что тест падает, если убрать защиту.
